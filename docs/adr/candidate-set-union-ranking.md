# ADR：候选疾病集用并集 + 命中数排序，而非严格交集

日期：2026-10-21
状态：已接受

## 背景

追问分诊需要一份「候选疾病集」，作为追问选症状和最终分级建议的依据。最初按第 7.2 节
的设计，用「已采集症状的交集」来算候选集：反查 `disease_symptoms`，取同时关联所有已采集
症状的疾病。这样逐轮叠加症状，候选集单调收窄。

但实测发现：一旦用户描述的症状不属于同一疾病（例如「最近总是累，还拉肚子」——乏力与腹泻
在知识库里没有任何疾病同时覆盖），交集就为空。此时系统会把「确实不舒服的患者」判成无候选，
直接停止追问并给出最保守的「观察」建议，丢弃了已采集的症状信息。

## 决策

候选疾病集 = **匹配任一已采集症状的疾病（并集）**，按「命中症状数」降序、`id` 升序排列。
候选集永不塌空，命中越多症状的疾病排得越靠前。

## 备选方案

- 严格交集：被否。空交集会把多症状但非单一疾病的患者误判为无候选。
- 交集为空时回退并集：可行，但引入逻辑分叉，本质仍是「交集优先」的补丁。
- 软收窄（按命中数打分取 top-K）：作为第 4 周在并集排序基础上的进一步收窄手段。

## 后果

- 「逐轮缩小」不再依赖交集，改为依赖命中数排序；第 4 周用它把高置信子集收敛到 top-N。
- 候选集可能包含命中数很少的疾病，排序是主要的置信信号。
- 当前种子规模小（31 个疾病），排序的区分度有限；第 4 周达标「首轮 15-20 → 第 3 轮 ≤5」
  时大概率需要扩充种子数据。
