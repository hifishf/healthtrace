# ADR：追问回答用 LLM 结构化语义判定，状态更新仍由确定性代码执行

日期：2026-10-22
状态：已接受

## 背景

追问分诊需要判断用户回答是肯定、否定、方向相反还是无关。最初用关键词子串匹配：
「体重有点上升」因为包含「有」被误判为对「有没有体重下降」的肯定，系统误回填
「体重下降」，候选集随之外扩到含「黑便」的疾病，产生错误追问和错误建议。
文字匹配覆盖不了语义，这类误判会直接污染医学结论。

## 决策

1. LLM 负责语义理解：在症状抽取的同一次结构化输出里返回 `answer_verdict`
   （affirm / deny / contradict / unrelated / unclear / not_applicable），
   输入包含「上一轮追问 + 用户回答 + 画像」。
2. 代码负责状态更新：affirm → 回填待问症状；deny / contradict → 记入排除；
   unrelated / unclear → 交给症状抽取正常走。LLM 不直接修改状态。
3. 关键词匹配（answer_polarity / contradicts_pending）降级为 LLM 判不清时的兜底。
4. 安全关键路径（红旗、硬上限、候选集、分级算级别）仍完全确定性，不依赖 LLM。

## 备选方案

- 纯关键词匹配：被否，语义覆盖不了（本次事故）。
- 纯 LLM 直接改状态：被否，不可审计、难测试、易被提示词注入带偏。
- 单独一次 LLM 判定调用：可行，但多一次成本/延迟；合并进现有抽取调用更省。
- 用向量/语义相似度匹配：对方向性语义（上升 vs 下降）仍不可靠，且难解释。

## 后果

- 语义理解更准，「衣服都松了」这类无关键词回答也能正确回填。
- LLM 可能判错，需兜底、测试与 trace；`answer_verdict` 应写入 trace 便于归因（待补）。
- 每次追问仍只有一次抽取调用，成本不因新增判定而翻倍。
