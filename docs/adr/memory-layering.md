# ADR：四层记忆分层——Redis 工作记忆与 Postgres checkpointer 职责分离

日期：2026-10-26
状态：已接受

## 背景

第 7 周要做跨会话记忆：新会话不再重复问已知信息。必须把「这一场问过什么」和
「图挂起在哪、下一步是什么」分开——前者是应用自己的业务概念，后者是 LangGraph 机制；
两者生命周期也不同：会话态用完即弃，断点要长期保留以便续跑和审计。

## 决策

四层记忆各归其位：

1. 工作记忆存 Redis：`ht:wm:{user}:{thread}` hash，存本轮轮次 + 已采集槽位，TTL 默认 3600 秒，会话结束 clear；
2. 图执行状态存 LangGraph Postgres checkpointer：断点续跑 / 审计；
3. 情景记忆存 PostgreSQL：chat / triage / insight / report 都记，可检索可删；
4. 语义记忆存 PostgreSQL：画像 30+ 语义字段，增量更新。

Redis 不可用时工作记忆静默降级为 no-op，不阻断主流程——长期事实不依赖它。

## 备选方案

- 只靠 checkpointer 存业务态：被否，把应用态塞进图状态破坏边界、难清理。
- Redis 存长期画像 / 情景：被否，有丢失风险且无结构化查询，Postgres 才是事实源。
- 单用户就地变量、不引 Redis：能跑，但为演示多用户 / 多并发下的热路径与缓存隔离，仍引入。

## 后果

- 职责清晰，可讲清「业务会话态 vs 图执行态」为什么不是重复造轮子。
- 单用户 MVP 下 Redis 冗余，真实价值在多用户 / 多并发；TTL 过期只丢可重建热态。
- 第 10 周知识记忆（pgvector RAG）作为第五层只读接入，不动前四层。
